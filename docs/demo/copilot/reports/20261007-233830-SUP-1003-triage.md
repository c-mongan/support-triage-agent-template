## 🗺️ How It Works (and Where It Breaks)
The UI export takes the table's result set in its current sort order and writes at most 10,000 rows. Rows beyond that are dropped, and a banner in the dialog states this. The customer's file has 10,000 rows from a 48,212-row table, which is consistent with that cap.

## 🎯 Root-Cause Assessment
**Assessment:** 🎯 The export hit the documented 10,000-row UI cap (rows 1 and 3). It is not a defect. The workaround is the Query API with cursor pagination, or batching by date range (rows 2 and 3).
**Confidence:** Likely based on pattern match
**Reasoning:** The exact row count matches the documented limit, and BEACON-097 describes the same behaviour. Documentation and a tracker entry alone cannot give `Confirmed by data`. No customer export logs were available.
**Not explained:** Whether the customer saw the limit banner, and whether their plan includes the warehouse export. Confidence is limited by lack of project data access.

Hi Sam,

Thanks for the detail. The 10,000-row figure is a limit on the Export CSV button, not a fault with your data. The export dialog also shows a banner that states the limit.

For your finance reconciliation, you have two options that the documentation describes:

1. Use the Query API with cursor pagination (GET /api/v2/query with the cursor parameter) to pull the full March result set.
2. Narrow the date range, for example to a week at a time, and export each batch separately. Each batch needs to stay under 10,000 rows.

The documentation also mentions a scheduled warehouse export on plans that include it. A support engineer can confirm whether your plan includes it.

A larger single-file CSV export is on our backlog as a feature request, and no delivery date has been set.

Please let us know if you would like help setting up either approach.
